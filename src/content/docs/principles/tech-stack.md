ここでは、特に指定がないプロジェクトで使う技術と、それを選んだ理由をまとめます。プロジェクトですでに使っている技術がある場合は、そちらに合わせます。

最終確認日：2026-11-18

## 言語と実行環境

| 用途 | 採用 | 理由 |
| :-- | :-- | :-- |
| 言語 | TypeScript | 型によって、誤りを実行前に見つけられます。型が、関数や部品の使い方を示す説明書にもなります |
| 実行環境 | Node.js（LTS版） | 長期サポートの版を使い、更新の頻度とサポート切れのリスクを抑えます |
| パッケージ管理 | npm | Node.jsに標準で付いてくるため、追加の導入が要りません。どの環境でも同じ手順で動かせます |

## フレームワーク

用途によって使い分けます。

| 用途 | 採用 | 理由 |
| :-- | :-- | :-- |
| ログイン後に使う管理画面やツールなど、検索エンジンに載せる必要がないアプリ | Vite + React | 構成が単純で、開発中の反映が速く、静的なファイルとしてどこにでも配置できます |
| 検索エンジンに載せるサイトや、サーバー側の処理が必要なアプリ | Next.js | サーバー側で描画でき、表示の速さと検索エンジン対策を両立できます。ルーティングやデータ取得の仕組みもそろっています |

## スタイリング

| 用途 | 採用 | 理由 |
| :-- | :-- | :-- |
| Reactのコンポーネント | CSS Modules | クラス名がコンポーネントごとに閉じるため、名前の衝突を気にせずに書けます。中身は標準のCSSなので、ブラウザの新しい機能をそのまま使えます |
| Reactを使わないサイト、全体に効かせるスタイル | 素のCSS | ビルドの仕組みに依存せず、ブラウザの標準の機能だけで管理できます |

## コードの検査と整形

| 用途 | 採用 | 理由 |
| :-- | :-- | :-- |
| TypeScriptとReactの検査 | Oxlint | 動作が非常に速いため、保存のたびやコミットの前に気軽に実行できます |
| コードの整形 | Oxfmt | Oxlintと同じOxcのツールで、速く、設定も少なく済みます |
| HTMLの検査 | Markuplint | HTMLの仕様に沿っているかと、アクセシビリティ上の問題を、JSXも含めて検査できます |
| CSSの検査 | Stylelint | CSSの誤りや、規約に合わない書き方を検査できます。CSS Modulesにも使えます |

機械的に判定できるルールは、これらのツールの設定に落とし込みます。詳しくは[フォーマットとLint](/coding-guidelines/common/format-and-lint/)に書きます。

## テスト

| 用途 | 採用 | 理由 |
| :-- | :-- | :-- |
| 単体テスト、コンポーネントのテスト | Vitest + Testing Library | Viteと同じ設定で動き、速く実行できます。Testing Libraryは、使う人と同じ操作でコンポーネントを確かめられます |
| E2Eテスト | Playwright | Chromium、Firefox、WebKitの3つのブラウザエンジンで同じテストを動かせます |

テストをどこまで書くかは[テスト方針](/coding-guidelines/quality/testing/)に書きます。

## 検討したが採らなかった技術

| 技術 | 採らなかった理由 |
| :-- | :-- |
| Tailwind CSS | HTMLにスタイルの指定が混ざり、構造が読みにくくなるためです。標準のCSSの書き方から離れることも避けたいと考えました |
| CSS-in-JS | 実行時にスタイルを生成する方式は、表示を遅くすることがあるためです |
| ESLint + Prettier | 実績はありますが、OxlintとOxfmtのほうが速く、設定も少なく済むためです |
| Biome | 速さは十分ですが、Oxlintと比べて検査できるルールの範囲で劣るためです |
| Jest | Vitestのほうが、ViteやTypeScriptと組み合わせるときの設定が少なく済むためです |
| pnpm、Yarn | 速さやディスク容量では有利ですが、npmで困っておらず、導入の手間を増やしたくないためです |

## 更新の方針

- 依存しているパッケージは、月に1回を目安に更新します
- メジャーバージョンの更新は、変更点を確認してから個別に行います
- 新しい技術を標準に加えるときは、このページを更新し、選定理由を書きます
