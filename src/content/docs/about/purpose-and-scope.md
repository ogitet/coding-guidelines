この規約は、私がWebのフロントエンドを実装するときに守るルールをまとめたものです。

## 目的

### 品質の基準を公開する

どのような基準でコードを書いているかを公開し、一緒に仕事をする人が、事前に品質を判断できるようにします。

### AIに同じ基準で書かせる

ClaudeなどのAIにコードを書かせるときも、この規約を指示として渡し、私が書くときと同じ基準で書かせます。そのため、規約はAIが読んでも判断に迷わないように、ルールを言い切る形で書いています。

### 判断を毎回やり直さない

一度決めた書き方とその理由を残し、同じことで迷う時間を減らします。理由も残しておくことで、前提が変わったときに、ルールを見直すべきかを判断できるようにします。

## 対象範囲

### 対象とする技術

- HTML
- CSS
- TypeScript（JavaScriptを含む）
- React

技術ごとのルールは「技術別ルール」の章に、技術に依らないルールは「共通ルール」の章にまとめています。

### 対象とする作業

設計から公開までの、実装に関わる作業を対象にします。

- コードを書く
- テストと検証
- Gitの運用とレビュー
- AIへの指示と、AIが書いたコードのレビュー

### 対象外

- 上記以外の言語（サーバーサイドの言語など）とインフラ
- デザインやコピーライティングなど、実装以外の作業

## ほかの規約との関係

参加するプロジェクトに独自の規約がある場合は、そちらを優先します。この規約は、プロジェクトの規約が決めていない部分にだけ適用します。

## ルールの読み方

各ルールには、どの程度守るかを示す準拠レベル（必須・推奨・任意）を付けています。意味は[準拠レベルの定義](/coding-guidelines/about/compliance-levels/)を参照してください。

## AIに読ませる場合

規約の全文を、AIが読みやすいテキスト形式でも公開しています。

- [llms.txt](/coding-guidelines/llms.txt)：規約の案内
- [llms-full.txt](/coding-guidelines/llms-full.txt)：規約の全文
- [llms-small.txt](/coding-guidelines/llms-small.txt)：規約の全文から補足を省いた短縮版
