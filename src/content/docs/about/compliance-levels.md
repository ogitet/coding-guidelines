---
title: 準拠レベルの定義
description: 各ルールに付ける準拠レベル（必須・推奨・任意）の意味と、ルールから外れるときの扱い。
---

この規約のルールには、必須・推奨・任意のいずれかの準拠レベルを付けています。準拠レベルは、そのルールから外れてよいかどうかと、外れるときに何をするかを表します。

## レベルの一覧

| レベル | 意味 | 外れるとき |
| :-- | :-- | :-- |
| 必須 | 常に守ります | 技術的に守れない場合だけ外れます。理由を該当箇所のコメントに書きます |
| 推奨 | 原則として守ります | 守らないほうがよい理由があれば外れます。理由をコメントかプルリクエストに書きます |
| 任意 | 採用するかをプロジェクトごとに決めます | 理由は書きません。ただし、同じプロジェクトの中では書き方を統一します |

## 必須

守らないと、不具合やセキュリティ上の問題、保守しにくいコードに直結するルールに付けます。

レビューで違反が見つかったら、必ず修正します。「時間がない」「好みに合わない」は、外れる理由になりません。外れてよいのは、ライブラリの制約などで技術的に守れない場合だけです。その場合は、該当箇所のコメントに理由を書きます。

```ts
// 規約の例外（any を使わない）：ライブラリの型定義が誤っており、any でしか受け取れないため
```

## 推奨

守ったほうが読みやすさや保守性が上がるものの、状況によっては別の書き方のほうがよいこともあるルールに付けます。

特に理由がなければ守ります。外れる場合は、そのほうがよい理由を説明できるようにしておき、コメントかプルリクエストの説明に書きます。

## 任意

どちらの書き方でも品質に差が出にくく、統一することに価値があるルールに付けます。

採用するかはプロジェクトごとに決め、採用しない場合も理由は書きません。ただし、同じプロジェクトの中で書き方を混ぜないようにします。既存のコードがある場合は、その書き方に合わせます。

## ページでの表記

各ルールでは、ルールの文のすぐ下に「準拠レベル：必須」の形で書きます。

## AIにコードを書かせる場合

ClaudeなどのAIにコードを書かせるときも、同じ準拠レベルを適用します。

- 必須と推奨は、指示しなくても守らせます
- 必須または推奨から外れた場合は、外れたルールと理由を報告させます
- 任意は、既存のコードの書き方に合わせさせます
