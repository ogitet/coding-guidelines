ここでは、動作を保証する範囲を決めます。この範囲をどう確かめるかは[検証](/coding-guidelines/quality/verification/)に書きます。

プロジェクトの要件で対応範囲が指定されている場合は、そちらを優先します。

## 対応ブラウザ

次のブラウザの最新版で動作を保証します。

| ブラウザ | 環境 |
| :-- | :-- |
| Chrome | Windows、macOS、Android |
| Edge | Windows |
| Firefox | Windows、macOS |
| Safari | macOS、iOS、iPadOS |

Internet Explorerには対応しません。

## 使ってよいWebの機能

HTML、CSS、JavaScriptの機能は、[Baseline](https://web.dev/baseline)を基準に使ってよいかを判断します。Baselineは、主要なブラウザで使える状態になったWebの機能を示す指標です。

| Baselineの状態 | 扱い |
| :-- | :-- |
| Widely available（広く利用可能） | そのまま使ってよい |
| Newly available（新たに利用可能） | 使えない環境でも内容を見られ、操作できるなら使ってよい |
| Limited availability（限定的） | 使えない環境でも困らない、見た目の補強にだけ使ってよい |

たとえば、Newly availableの機能でアニメーションを付ける場合、その機能が使えない環境ではアニメーションなしで表示されれば問題ありません。

## 画面サイズ

画面の幅が320pxから、横幅いっぱいまでのすべての幅で、表示が崩れず、内容を読めるようにします。

- 幅320pxでも、横にスクロールしないで読めるようにします
- 特定の端末の幅に合わせるのではなく、どの幅でも崩れないように作ります
- ブラウザの拡大表示や文字サイズの変更で、200%まで大きくしても内容が欠けないようにします

320pxは、小さいスマートフォンの幅であると同時に、パソコンで400%に拡大したときの幅にも当たります。

## 操作方法

次のどの方法でも、すべての機能を使えるようにします。

- マウス
- タッチ操作
- キーボード
- スクリーンリーダーなどの支援技術

ホバーしないと表示されない情報や、キーボードで操作できない部品を作りません。詳しくは[アクセシビリティ](/coding-guidelines/quality/accessibility/)に書きます。

## ユーザーの設定

OSやブラウザでユーザーが選んだ設定を尊重します。

- 動きを減らす設定（`prefers-reduced-motion`）のときは、大きな動きを止めます
- ダークモード（`prefers-color-scheme`）に対応するかは、プロジェクトごとに決めます

## 対象外

- 印刷用のレイアウト（プロジェクトの要件で必要な場合だけ対応します）
- JavaScriptを無効にした環境での完全な動作（ただし、内容を読めることは目指します）
